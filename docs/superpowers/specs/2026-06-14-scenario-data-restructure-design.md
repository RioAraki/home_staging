# 关卡数据重构：单文件 YAML → 每关独立 JSON 源

日期：2026-06-14

子项目 1（关卡编辑器的前置）。

## 背景

唯一源头是 `md/maps_data.yaml`（27 关，单文件）。两个消费方都最终读它：
- cocos：`cocos/home-staging-cocos/tools/yaml2json.cjs`（npm `data:build`）读 yaml → `assets/resources/data/maps_data.json`。
- app/：`app/src/data/index.ts` 直接 `import '@data/maps_data.yaml'`（`@data` → `md/`）。

要做关卡编辑器，需要每关一个独立、JSON-native 的源文件，新关卡与现有关卡同构。

## 目标

把 `md/maps_data.yaml` 拆成每关一个 `md/scenarios/<id>.json` 作为**新源**；打包脚本读这些 JSON 重新生成 `md/maps_data.yaml`（仍是两个消费方读的成品包）。**cocos / app 加载代码零改动。**

## 组件

依赖 `js-yaml` 仅存在于 `cocos/home-staging-cocos/node_modules`，故脚本放 `cocos/home-staging-cocos/tools/`（与 yaml2json.cjs 同目录、同 ROOT 相对路径写法），用 cocos npm 脚本调用。

### 1. 拆分（一次性）`tools/scenarios-split.cjs`
- 读 `md/maps_data.yaml` → 对每个 scenario 写 `md/scenarios/<id>.json`（2 空格缩进、`ensureAscii=false`、结尾换行）。
- 写顺序清单 `md/scenarios/_index.json` = 按原 yaml 中的顺序排列的 id 数组（保留 training 在前等次序）。

### 2. 打包（常驻）`tools/scenarios-bundle.cjs`
- 读 `_index.json` 定序；清单里没列、但 `md/scenarios/` 下存在的 `<id>.json` 按字母序追加（保证新文件不丢）。
- 依次读各 `<id>.json` → 组装 `{ scenarios: [...] }` → `yaml.dump` 写回 `md/maps_data.yaml`，顶部加注释行
  `# AUTO-GENERATED by tools/scenarios-bundle.cjs from md/scenarios/*.json — do not edit by hand.`

### 3. 接线（cocos package.json scripts）
- `scenarios:bundle` = `node tools/scenarios-bundle.cjs`
- `scenarios:split`  = `node tools/scenarios-split.cjs`（一次性/需要时）
- `scenarios:build`  = `node tools/scenarios-bundle.cjs && node tools/yaml2json.cjs`（打包 + 出 cocos JSON）
- app 端不变（继续 import 生成出的 maps_data.yaml）。

### 4. 正确性验证（测试）`tests/scenariosRoundtrip.test.ts`
- 解析原始 `md/maps_data.yaml`（重构前的内容，作为基线快照），与「拆分→打包后重新解析」的结果**逐 scenario deep-equal**。
- 实操：测试读 `_index.json` + 各 `<id>.json` 重新组装，与 cocos 已生成的 `maps_data.json`（重构前后保持不变）deep-equal，证明数据零变化。

## 验证步骤（实现时执行）
1. 跑 split → 生成 27 个 json + _index.json。
2. 跑 bundle → 重生成 maps_data.yaml。
3. 跑 yaml2json → 重生成 cocos maps_data.json。
4. 与重构前的 maps_data.json deep-equal（git 对比 + 测试）。
5. `git diff --stat` 确认 maps_data.json 内容无语义变化（可能仅键序/格式）。

## 风险 / 取舍
- maps_data.yaml 从手写源变为生成物：原 YAML 注释会丢失（可接受；它现在是 build artifact）。
- `js-yaml` dump 会重排键序/改风格；以 **deep-equal** 为正确性判据，语义不变即可。
- 键序变化可能让 maps_data.json 产生大 diff —— 用 deep-equal 测试而非字节比对来保证正确。
